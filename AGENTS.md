# AGENTS.md — инструкции для AI-агентов

Это общий документ для любого AI-агента (Claude, Codex, Cursor и др.), который продолжает работу над проектом. Здесь собраны правила и договорённости, полученные от владельца проекта в ходе работы. **Прочитай целиком перед любыми изменениями.** Если получишь новую устойчивую инструкцию от владельца — допиши её сюда (раздел «Журнал решений»).

---

## 1. Что это за проект

**«Журнал отдела птиц»** (Dziennik działu ptaków / Bird department log) — мобильное веб-приложение (PWA) для ведения документации в отделе птиц зоопарка.

- Владелец: Демид (GitHub `Demidius`). Работает с птицами в зоопарке в Польше.
- Пользователи: 5–10 сотрудников отдела, вход по **логину и паролю, без e-mail**.
- Сайт: https://demidius.github.io/bird-department-log/ (GitHub Pages, ветка `main`, корень репозитория).
- Репозиторий: `Demidius/bird-department-log`.
- Бэкенд: Supabase, проект `nszeqgopzonpplfznaat` (имя `zoo-bird-department`).
- Владелец рисует экраны от руки и присылает фото эскизов/табличек — их надо воспроизводить максимально близко.

### Что умеет приложение
- **Записи событий** (`records`): наблюдение, смена экспозиции (перевод между вольерами), назначение лечения / подача лекарств / окончание лечения, снесла яйцо, начала насиживать, выклёвывание, выход из гнезда, роды (`birth`, для млекопитающих) и т. д. Ключи — `ev_*` в `i18n.js`.
- **Предположительные события** (расчётные, в базу не пишутся, `calItems` → `guess`): от начала насиживания — выклев (`incub_days`) и выход из гнезда (+`fledge_days`); от выклева — выход из гнезда; от родов — оплодотворение (−`gest_days`). В календаре — кружок-контур, в шторке дня — блок «Ожидается». Исчезают, когда внесено настоящее событие.
- **Сейчас**: счётчики (на лечении, насиживают, птенцы).
- **Календарь** (список / сетка). В сетке число дня кликабельно: шторка `#sheet-day` (`openDay`/`renderDay`) — записи дня, периоды (насиживание/лечение), кнопки «добавить запись» с этой датой (`data-new` + `data-at`).
- **Коллекция** (`collection`): отдельные птицы или **группы** (животные одного вида, которых не разделяют) — имя, вид, пол, кольцо, чип, даты, происхождение, вольер, статус, фото, альтернативные имена. Имя необязательно: если пусто, создаётся из названия вида (+ кольцо, или «— группа», + номер при совпадении). Имя остаётся ключом связи с записями (`records.bird`) и уникально в базе.
- Группа: колонка `collection.grp jsonb` = `{m, f, u, j}` (самцы, самки, пол неизвестен, молодые). Показывается как «♂ 3 · ♀ 4 · ? 1 · молодые 2 (3.4.1, всего 10)». У группы пол/кольцо/чип не заполняются. Замок поля — ключ `grp`.
- **Вольеры** (`enclosures`): иерархия (здание → вольера → клетка …), тип, площадь, вместимость.
- **Справочник видов** (`species`): названия RU/PL/EN/латынь + карточка `info` (см. §5).
- **Фото** у записей, птиц, видов, вольеров (bucket `journal-photos`, превью `*_t.jpg`).
- **Журнал изменений** (`change_log`) с вкладками: все / пользователи / AI / разработка.
- **Пользователи** (только админ), экспорт CSV, офлайн-оболочка (service worker).

## 2. Общение с владельцем

- Отвечать **по-русски**, **кратко** — владелец обычно читает с телефона.
- В отчёте: что сделано, что не удалось/что сомнительно, что проверить. Без пересказа всех шагов.
- **Не выдумывать данные.** Прямая цитата владельца: «Если не можешь найти данные, то не придумывай». Нет источника — поле остаётся пустым, и об этом сообщается владельцу.
- Если инструкция неоднозначна и владелец сказал «сделай как оптимальнее» — выбирай сам и коротко объясни выбор.
- Названия видов на русском, придуманные/подобранные агентом, помечать как непроверенные.

## 3. Безопасность — жёсткие правила

1. **Никогда** не запрашивать, не хранить и не выводить `service_role` ключ Supabase. В клиенте только publishable key (`SB_KEY` в `app.js`).
2. **Права администратора** получает только сам пользователь кнопкой «claim first admin» (`rpc('claim_first_admin')`). **Никогда** не выдавать роль `admin` через SQL.
3. Управление аккаунтами — только через Edge Function `supabase/functions/admin-users` (проверяет активного админа; ключ service_role живёт только в секретах функции).
4. RLS включён на всех таблицах. Не ослаблять политики. Роли: `admin`, `staff` (пишет), `viewer` (только чтение).
5. Уважать **замки** (§6): при записи от имени AI не менять поля, перечисленные в `locked`.

## 4. Технологии и структура

Чистый HTML/CSS/JS без сборки и фреймворков. Supabase JS v2 с CDN (с `integrity`).

```
index.html            основная разметка + базовые стили (<style> с CSS-переменными)
desktop.css           дополнительные стили: шторка загрузки, десктоп-раскладка, журнал, замки, переводы
app.js                вся логика (~160 КБ, один файл, блочная область видимости)
i18n.js               словарь интерфейса DICT {ru, pl, en}
i18n-species.js       тексты карточки вида (дополняет DICT)
pwa.js, sw.js         установка PWA и офлайн-кэш (network-first с cache:'no-cache', кэш 'zoo-log-v2')
manifest.webmanifest, icon.svg, icon-maskable.svg
supabase/functions/admin-users/index.ts   Edge Function для аккаунтов
tests/                браузерные тесты (Playwright + поддельный Supabase), см. tests/README.md
AGENTS.md             этот файл
```

Порядок скриптов в `index.html`: supabase-js → `i18n.js` → `i18n-species.js` → `pwa.js` → `app.js`.

### Договорённости по коду
- Новые элементы интерфейса **добавляются из `app.js`** (функция `add(selector, where, html)` при старте), а `index.html` по возможности не трогаем.
- Все строки интерфейса — только через `t('key')` и `DICT` во **всех трёх языках** (ru, pl, en). Склонения — массивы форм + `pw(n, key)`.
- HTML из данных — только через `esc()`.
- Иконки — внутренний набор SVG `I` / `ic(name)`, атрибут `data-ic`.
- Логины превращаются в псевдо-почту `<login>@zoo-log.invalid` (`LOGIN_DOMAIN`).
- Навигация через History API (`navStart`, `navState`, `setTab(v, fromBack)`, обработчик `popstate`). Кнопка «назад» телефона возвращает на предыдущий экран, а на корневом экране спрашивает подтверждение выхода (`cf_exit`). **Не ломать** — это была отдельная жалоба владельца («если нажать назад, сразу выходит из программы»).
- Шторка загрузки: `body::before` с SVG (птички кружат вокруг яйца) в `desktop.css`; скрывается классом `body.ready`; `splash()` держит её минимум 700 мс; CSS-страховка — исчезает сама через 20 с.

## 5. База данных (Supabase)

Таблицы `public`:
- `profiles` (id, login, display_name, role, active)
- `species` (name_ru, name_pl, name_en, latin, note, **info jsonb**)
- `collection` (name, species_id, sex, ring, chip, born, arrived, origin, encl, encl_at, status, note, names jsonb, locked jsonb, grp jsonb)
- `enclosures` (name, kind, area, size, capacity, active, parent_id, names jsonb, locked jsonb)
- `records` (type, species_id, bird, event_at, f jsonb, note)
- `photos` (owner_type, owner_id, path, width, height)
- `change_log` (at, actor, kind, entity, entity_id, action, label, fields[], extra, summary, ver)
- `birds`, `bird_events`, `department_members` — старая схема, приложение их не использует.

Схема `app` (функции и триггеры): `log_change`, `change_log_ver`, `species_locks`, `row_locks`, `touch`, `collection_sync`, `enclosure_sync`, `enclosure_no_cycle`, `drop_owner_photos`, `can_read`, `can_write`, `is_admin`, `my_role`.

### Журнал изменений
- Каждое изменение данных пишется триггером `app.log_change`.
- `kind`: `user` — человек; `ai` — запись без `auth.uid()` (агент через SQL); `dev` — запись о новой версии приложения.
- У каждой записи есть номер (`id`, показывается как «№…»). У `dev` автоматически растёт `ver` (триггер `change_log_ver`), и **версия приложения в настройках** = максимальный `ver`.
- **После каждого заметного изменения кода добавляй запись `dev`** с кратким описанием на русском (summary), например:
  ```sql
  insert into public.change_log (kind, entity, action, summary) values ('dev','app','note','Кратко: что изменилось');
  ```
  Summary пишется по-русски, понятно пользователю (не технично). На момент написания последняя версия — v25.

### Карточка вида `species.info`
- Переводимые поля (`TRK`): `size, life, order, family, range, habitat, diet_wild, behaviour, breeding, diet_zoo, husbandry, health, sex`.
- Формат переводимого поля: `{"ru": "...", "pl": "...", "en": "...", "src": "pl", "auto": [...], "fix": [...]}`.
  - `src` — язык-источник; `auto` — языки, переведённые автоматически; `fix` — авто-переводы, исправленные человеком (их больше не перезаписывать).
  - Простая строка = старый формат, считается русским текстом.
- Автоперевод делается на клиенте через MyMemory API (`translateDirty`, `stashTr`, `fillTr`, `trPick`, `trNote`).
- Прочие ключи: `incub_days` (число), `fledge_days` (дней от выклева до выхода из гнезда), `gest_days` (беременность, дней) — только из источников, `incub_range` (строка, напр. `"26–28"`), `iucn` (`LC/NT/VU/EN/CR/EW/DD`), `cites`, `group` (`bird` и др.), `syn`, `main`, `locked`.
- Фото вида с Wikimedia Commons:
  ```json
  "photo": {"src": "https://commons.wikimedia.org/wiki/Special:FilePath/<File>?width=960",
            "thumb": "https://commons.wikimedia.org/wiki/Special:FilePath/<File>?width=330",
            "page": "https://commons.wikimedia.org/wiki/File:<File>",
            "credit": "<автор или 'Wikimedia Commons'>"}
  ```
- Когда агент пишет тексты сам — все три языка, `src: "pl"`, без `auto`.

## 6. Замки (locks)

Пользователь может «закрыть замком» поле, чтобы его не перезаписали ни другие, ни AI.
- Вид: `species.info.locked` — массив имён полей (`latin`, `name_ru`, `name_pl`, `name_en`, ключи `info`), `'*'` = вся карточка.
- Птицы и вольеры: колонка `locked jsonb` (`BIRD_LOCK`, `ENCL_LOCK`).
- Защита на уровне БД: триггеры `app.species_locks`, `app.row_locks`.
- Шаблон безопасной записи от AI:
  ```sql
  update public.species s
  set info = coalesce(s.info,'{}') || (patch - array(select jsonb_array_elements_text(coalesce(s.info->'locked','[]'))))
  where ... and not coalesce(s.info->'locked','[]') ? '*';
  ```
- Замки должны быть везде, где пользователь вводит важные данные (требование владельца «замки сделай везде, где они могут быть нужны»).

## 7. Дизайн

Концепция (из комментария в `index.html`):
- **Голос:** спокойный, практичный рабочий инструмент для смотрителей; без украшательства.
- **Идея:** бумажный журнал и планшет смотрителя, превращённые в приложение для телефона.
- **Цвета:** холодный почти-белый фон, лесной зелёный акцент; статусы — красный / янтарный / синий. Светлая и тёмная темы через `light-dark()`.
  - `--accent` `#1E6B4E` / `#66CDA1`, `--bg` `#E6EBE8` / `#0A0F0D`, `--app` `#F3F5F4` / `#111816`, `--card` `#FFFFFF` / `#18211D`, `--ink` `#15211C` / `#E8EEEB`, `--red` `#B42318`, `--amber` `#9A4A00`, `--blue` `#1D5FA8` (+ `-soft` / `-ink` варианты).
  - Всегда использовать CSS-переменные, а не жёсткие цвета.
- **Шрифты:** Manrope (заголовки, 600–800), Inter (текст, 400–700).
- **Раскладка:** одна колонка телефона до 480px, липкие счётчики сверху, липкие вкладки снизу, «шторки» (sheets) выезжают снизу. На десктопе — расширенная раскладка из `desktop.css`.
- Крупные кнопки событий, удобные одной рукой; состояния фокуса и `aria-*` сохранять.
- Тема-цвет PWA `#1E6B4E`.

## 9. Как деплоить

- `git push` из песочницы раньше был заблокирован (403), в ноябре 2026 заработал (`git -c push.negotiate=true push origin <ветка>:main`). Если снова 403 — публикация через GitHub API / MCP (`create_or_update_file` с полным содержимым и актуальным `sha`, или `push_files`).
- После публикации **проверить**, что удалённый файл совпадает с локальным:
  `git fetch -q origin main && git show origin/main:app.js | cmp - app.js`
- MCP может превращать JS-экранирования невидимых символов (обратный слэш + `uFEFF` / `uffff`) в сами невидимые символы — функционально это то же самое; после публикации синхронизируй локальную копию с удалённой.
- Если меняются связанные файлы (например, CSS и JS шторки) — публиковать их **сразу друг за другом**, иначе на сайте окажется полуготовое состояние (так уже было: шторка висела без JS, который её скрывает).
- Перед публикацией — прогон тестов из `tests/` (см. `tests/README.md`) и просмотр скриншотов, включая ширины 320–1440px и тёмную тему. Для новой функции — добавь тест по образцу существующих. Тесты работают с поддельным Supabase и не трогают настоящую базу.
- Сеть песочницы: Wikipedia/Commons из shell недоступны; для поиска данных и имён файлов Commons использовать веб-поиск.

## 11. Журнал решений (дописывать сюда)

- Аккаунты логин+пароль без e-mail; 5–10 человек; роли admin/staff/viewer.
- Фото у записей, птиц, видов и вольеров.
- Интерфейс и данные на трёх языках; польский по умолчанию.
- Журнал изменений с номерами, вкладками «все / пользователи / AI / разработка»; версия приложения в настройках из записей `dev`.
- Дни насиживания у видов — только из источников.
- Описания видов хранятся в трёх языках, недостающие переводятся автоматически; исправленный человеком перевод не перезаписывается.
- Замки на полях видов, птиц и вольеров; защищены триггерами в БД.
- Шторка загрузки с кружащими птичками.
- Кнопка «назад» не закрывает приложение сразу, а ведёт по истории; на главном экране — подтверждение выхода.
- Виды из таблички «Mieszkańcy hali wolnych lotów» добавлены и заполнены из интернет-источников (ноябрь 2026).
- Дни в календаре (сетка) кликабельны: открывается список записей дня и добавление записи на эту дату (ноябрь 2026).
- После публикации телефон мог до 10 минут показывать старый код (HTTP-кэш GitHub Pages), хотя версия в настройках уже новая (она из базы). Service worker теперь всегда сверяется с сервером (`cache: 'no-cache'`).
- Предположительные события считаются на лету из сроков вида (инкубация, выход из гнезда, беременность), в базу не записываются; новое событие «Роды» (ноябрь 2026).
- Имя птицы в коллекции необязательно (создаётся автоматически); можно добавить группу животных одного вида с составом по полу и молодым (ноябрь 2026).
