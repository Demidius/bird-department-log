# Дизайн: сайт → макет → сайт

Владелец прорабатывает интерфейс в макете (артефакт Claude типа **Design**), потом изменения переносятся на сайт. Код не трогать, пока владелец не скажет «переносим на сайт».

## Где что
- Design System «Журнал отдела птиц» (токены, шрифты, компоненты `bl-*`, иконки): https://claude.ai/artifact/7m3Vz1LgqVYtJDKR6sm2sd — основа любого макета; новые компоненты добавлять туда же.
- Старый макет приложения (21.11.2026, до многих доработок — только для истории): https://claude.ai/artifact/1s6S2pzy9EeJn3DL7HL72L
- Код сайта: `v2/` (см. `docs/code.md`), стили `v2/app.css`, иконки `v2/js/ds.js`.

## Этап 1. Сайт → новый макет
1. Снимки текущего сайта (сайт github.io из песочницы недоступен — снимаем локально тестом):
   `python3 tests/test_newui.py /tmp/shots` → PNG 390×844. Карта снимков:
   `n01` Сейчас · `n13` Журнал · `n17` Календарь · `n18` Ещё (тёмная, ru) · `n19` Сейчас (тёмная, ru) ·
   `n05` карточка животного · `n11` карточка вольера · `n21`/`n22` график температуры · `n16` карточка вида · `n14` карточка записи с комментариями · `n28` карточка группы без численности ·
   `n02` «+» → выбор животных · `n03` «Что записать?» · `n04` травма (несколько животных) · `n06` назначение лекарства · `n08` меню лечения · `n09` перенос · `n12` поступление · `n27` поступление группы без численности · `n20` роды · `n25` погода · `n15` правка записи · `n23`/`n24` шапка с кнопкой «обновить».
   Не хватает экрана — дописать шаг в `tests/test_newui.py` (не ломая существующие).
2. Посмотреть снимки, создать **новый** артефакт Design «Журнал отдела птиц — макет v2 (<дата>)» на Design System выше и перенести экраны артбордами 390×844, сгруппировав по разделам: главные экраны · карточки · добавление записи · формы · тёмная тема. Воспроизводить как на сайте (тексты по-польски, как в приложении; данные — из снимков, ничего не придумывать).
3. Дать владельцу ссылку. Дальше — правки по его словам и рисункам от руки; каждое изменение — отдельный артборд «было / стало» или пометка на артборде, чтобы потом было видно, что переносить.

## Этап 2. Макет → сайт (по команде владельца)
1. Прочитать макет, составить список отличий от сайта (экран → что меняется) и показать владельцу коротко.
2. Внести: стили — `v2/app.css` (токены не дублировать), новые функции — модулем-расширением `v2/js/<имя>.js` (см. `docs/code.md`), правки разметки — в нужном `v2/js/*.js`. Строки — в трёх языках.
3. Тест + снимки, сверить с артбордами; опубликовать одним коммитом; `select app.ai_dev('…')`; новые компоненты — в Design System; решение — строкой в `docs/decisions.md`.
