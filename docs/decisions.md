# Журнал решений владельца (дописывать в конец)

- Аккаунты логин+пароль без e-mail; 5–10 человек; роли admin/staff/viewer.
- Фото у записей, птиц, видов и вольеров.
- Интерфейс и данные на трёх языках; польский по умолчанию.
- Журнал изменений с номерами, вкладками «все / пользователи / AI / разработка»; версия приложения в настройках из записей `dev`.
- Дни насиживания у видов — только из источников.
- Описания видов хранятся в трёх языках, недостающие переводятся автоматически; исправленный человеком перевод не перезаписывается.
- Замки на полях видов, птиц и вольеров; защищены триггерами в БД.
- Шторка загрузки с кружащими птичками.
- Кнопка «назад» не закрывает приложение сразу, а ведёт по истории; на главном экране — подтверждение выхода.
- Виды из таблички «Mieszkańcy hali wolnych lotów» добавлены и заполнены из интернет-источников (ноябрь 2026).
- Дни в календаре (сетка) кликабельны: список записей дня и добавление записи на эту дату (ноябрь 2026).
- Телефон мог до 10 минут показывать старый код (HTTP-кэш GitHub Pages); service worker всегда сверяется с сервером (`cache: 'no-cache'`).
- Предположительные события считаются на лету из сроков вида, в базу не пишутся; событие «Роды» (ноябрь 2026).
- Имя животного необязательно (создаётся автоматически); группы животных одного вида с составом по полу и молодым (ноябрь 2026).
- Выбор животного в записи — выпадающим списком; после выклева/родов — предложение карточки потомства; родителей сколько угодно, включая группы (ноябрь 2026).
- Время в записи необязательно, только по кнопке (ноябрь 2026).
- Поиск в длинных выпадающих списках, клавиатура только по нажатию на поле поиска (ноябрь 2026).
- Экран «Пропущенные данные»: тип данных → виды без него → форма вида на этом поле (ноябрь 2026).
- В календаре вместо точек — значки событий в цвете группы; предположительные — в пунктирной рамке (ноябрь 2026).
- Вертикальное главное фото вида — целиком, горизонтальное заполняет рамку (ноябрь 2026).
- **Архитектура под работу с ИИ (22.11.2026)**: инструкции разбиты по задачам (AGENTS.md — маршрутизатор, подробности в `docs/`); `app.js` разделён на модули `js/`; заполнение данных — функциями БД `app.ai_*` (всё или ничего, только пустые поля, замки соблюдаются); схема БД и код Edge Function — в репозитории (`supabase/`); латынь вида уникальна; исправлено сохранение события «Роды» (тип `birth` не был разрешён в базе).
- Названия мест содержания остаются уникальными по всей базе (животные и переводы ссылаются на место по имени) (22.11.2026).
- **Новый дизайн (23.11.2026)**: сначала только телефон (планшет и ПК позже); выкатка рядом по адресу `/v2`, главный адрес переключить после проверки владельцем; без фреймворка.
- Путь записи: «+» → Карта животного / Вольеры / Свободная запись → карточка → «Добавить запись» → «Что записать?» (все группы на одном экране) → форма. Без «недавних» и «частых», ничего не выбрано заранее (кроме «Я» в «Кто переносил»).
- Группы записей с цветом: Здоровье, Наблюдение, Размножение, Содержание, Отдел. Две темы (светлая/тёмная) с переключателем.
- Несколько животных: общее поле для всех + индивидуальное по каждому; при переносе подрезка крыльев, вес, травмы, мечение — по каждой особи.
- Править запись могут автор и администратор, остальные — комментировать (с ответами). Конец лечения — из меню назначения, не отдельный тип. Поступление — только через Ещё → Животные.
- Старая версия отключена, основной адрес открывает новую (23.11.2026).
- Роды/выклев: в записи выбираются родители и кто родился; родители попадают в карточку детёныша (23.11.2026).
- Температура вольера: «Указать температуру» в записях про место и график в карточке вольера (23.11.2026).
- Данные обновляются сами (изменения других сотрудников приходят без перезагрузки); рядом с аккаунтом кнопка «обновить», подсвечена, если новые данные не загрузились (23.11.2026).
- Погода: в свободной записи пункт «Погода» — температура, небо, осадки, ветер, явления (23.11.2026).
- Группа может быть без точной численности: «Точная численность неизвестна» + необязательное «примерно сколько» (23.11.2026).
- Свободная запись: у Хозяйства, Дератизации, Поставки и Поломки свои поля; новая запись открывается с «Прочее» (23.11.2026).
- Выбор животного: сортировка по вольеру / названию / избранным; избранное хранится на устройстве (23.11.2026).
- Журнал: вид во второй строке выделен цветом; добавление записи — нижняя панель «Назад» на всю ширину (23.11.2026).
- «Сейчас»: задача открывает карточку записи; у лечения 2–3× в день и наблюдения «несколько раз в день» — время каждой подачи; кнопка «Подать» за 30 минут, раньше — «Подать в …» (23.11.2026).
- Цвет окна по типу: животные — светло-оранжевый, виды — шалфей, вольеры — серый, запись — голубой; секции карточек выразительнее (23.11.2026).
- Карточка вида открывается на вкладке «В зоопарке», она первая (23.11.2026).
- Дни в журнале разделены крупным зелёным заголовком и линией. В карте животного код IUCN сопровождается расшифровкой на языке интерфейса (25.11.2026).
- В назначениях расшифровываются сокращения способов введения, доступны варианты «В воду», «В корм» и «На кожу» (25.11.2026).
- В календаре под датой два счётчика: записи и предполагаемые события. У предполагаемых событий оранжевый значок часов. Нулевые счётчики скрыты (26.11.2026).
- Верхние счётчики экрана «Сейчас» открывают карточки животных по статусу и вкладку с отфильтрованными записями. Панель остаётся на экране и переключает статус в открытой вкладке (26.11.2026).
- Дополнительное кормление можно назначить при насиживании или отдельной записью. У каждой ежедневной подачи своё время и отметка в «Сейчас» (26.11.2026).
- В «Сейчас» карточки дополнительного кормления идут после лекарств, выше карточек насиживания (26.11.2026).
- Из «Сейчас» открывается карточка кормления с редактированием и завершением. Срок задаётся числом дней, до отмены или до окончания насиживания для связанного назначения (26.11.2026).
